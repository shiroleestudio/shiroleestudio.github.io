# shiroleestudio.github.io

이시로스튜디오(아기토끼 시로) 허브 사이트. GitHub Pages로 https://shiroleestudio.com 에 공개된다(저장소 `CNAME` 파일이 주소를 정한다. 도메인·DNS 는 `STUDIO.md`).

구성

- `index.html` — 첫 화면은 3D '시로의 집'(아래 절)만. 머리줄 · 무대(남는 높이 전부) · 층 버튼 · 한 줄 바닥글. 작품·소식·이야기·문의는 각자의 페이지에만 둔다. 제목·소개와 방 목록은 화면낭독기·검색엔진용으로 숨겨 두고, 3D 가 안 되면 방 목록이 보인다
- `works/` — 작품 목록, `works/timeline/`, `works/space-surfer/` 소개 페이지
- `news/` + `feed.xml` — 소식과 RSS(Atom). 새 소식은 두 곳에 함께 추가
- `about/` — 시로 이야기, `support/` — 자주 묻는 질문·문의
- `sitemap.xml`, `robots.txt`, `assets/og.png`(공유 이미지), `assets/img/`(스크린샷)
- `favicon.ico` — 루트에 꼭 둔다. 네이버 봇이 수집 때 `/favicon.ico` 를 요청하고 404 면 수집이 실패한다(연표에서 겪은 일). `assets/favicon-32.png` 에서 만든 16·32px 사본이라 아이콘이 바뀌면 함께 다시 만든다.
- `privacy/<앱이름>/` — 앱별 개인정보처리방침 (swingby, timeline, coffee)
- `ads.txt` — 웹 애드센스 판매자 확인(루트 도메인에 두면 timeline. 등 서브도메인까지 적용). 게시자 ID 는 애드센스 계정의 것.
- `app-ads.txt` — 애드몹 app-ads.txt (가입 후 한 줄 채움)
- `404.html` — 없는 주소 안내

규칙

- 외부 스크립트·폰트 없이 정적 파일만 쓴다. 경로는 상대경로(404.html만 절대경로).
- 머리말·꼬리말은 페이지마다 같은 마크업이 들어 있다. 메뉴를 바꾸면 모든 페이지를 함께 고친다.
- 아직 공개되지 않은 곳(예: itch.io 페이지)은 링크하지 않는다.
- 시로 그래픽은 캐릭터 시트 확정 전 임시 표현이다. `TODO(character-sheet)` 주석 참고.
- 개인 실명·소속·직업은 어디에도 넣지 않는다. 문의는 shiroleestudio@gmail.com.
- 릴리스마다 `CHANGELOG.md` 맨 위에 한 줄 추가하고 `vX.Y.Z` 태그를 남긴다.

운영

- 배포: `main` 에 푸시하면 GitHub Pages 가 그대로 올린다(빌드 없음, 1~2분). 상태는 Actions 탭의 "pages build and deployment".
- 되돌리기: 잘못 올라갔으면 `git revert` 로 커밋을 되돌려 다시 푸시한다. 설정을 만질 일은 없다.
- 깨졌을 때 볼 곳: Settings → Pages 의 Source 가 `main` / root 인지. 그 외에는 HTML 문법 오류뿐이다.
- 외부 계정·정기 점검·다른 저장소 목록은 `STUDIO.md`.
- 라이선스: 코드(HTML·CSS·JS)는 `LICENSE`(MIT). 시로 캐릭터 그림과 글은 이시로스튜디오의 것으로, MIT 에 포함되지 않는다.

## 시로의 집 (첫 화면의 3D 건물, 파일은 `building/`)

첫 화면의 주인공. 1층 찻집 · 2층 갤러리(화실+공방) · 3층 다락(놀이방·천문대) + 루프탑, 지붕 위 돔에서 망원경이 나온다. 지하실(돌방, 바깥 서쪽 돌계단으로 내려감) 북쪽 벽에는 블랙홀이 도는 관측창이 있다('블랙홀멍', 아래). 집 둘레는 게임의 한 장면처럼 동네 터(잔디·돌길·말뚝 울타리·나무·가로등·우편함·연못·뒤편 언덕, 모두 `floor 0`)이고, 배경은 셰이더가 그리는 하늘(라이트=낮, 다크=별 뜬 밤)이다. 화면 맞춤은 집(1~3층)만 잰다. 방 라벨이 곧 메뉴다. 같은 방 목록이 `index.html` 안에 글로 있다(평소엔 숨김, 3D 가 안 되면 보임). 방을 바꾸면 `ROOMS` 와 이 목록을 같이 고친다. `building/index.html` 은 첫 화면으로 넘기기만 한다.

- `building/house.glb` — 모델. **손으로 고치지 않는다.** `building/model/build_house.py` 를 고치고 다시 만든다:
  `pip install bpy pillow` (Python 3.11+, Blender 5.x) 후 `python building/model/build_house.py building/house.glb`, 또는 `blender -b -P building/model/build_house.py -- building/house.glb`.
  스크립트가 모양을 쌓은 뒤 ① 큰 면을 잘게 나누고 구석 그늘(AO)을 광선으로 재어 정점색 `COLOR_0` 에 굽고, ② `building/model/textures.py` 가 그린 나뭇결·지붕널·회벽·돌·풀 텍스처(WebP, 1 타일 = 1 m)를 상자 투영 UV 로 입힌다. 법선은 넣지 않는다(면이 평평해 사이트가 계산해도 같다, 용량 25% 절약). 결과는 약 2.3 MB(계단·지하실 포함).
  손그림 텍스처가 생기면 `textures.py` 의 `RECIPES` 에서 그 그림 파일로 바꿔 끼운다.
- `building/house.webp` + `assets/og.png` — 정지 그림. 3D 가 안 되는 기기와 공유 미리보기에 쓴다. 모델·그림체가 바뀌면 `building/model/still.js`(playwright 필요, 선택 도구)로 다시 찍는다.
- 모델과 코드의 약속: 노드 extras 의 `floor`(층, 0=땅, -1=지하실)·`cut`(S/N/E/W, 카메라가 그쪽이면 걷어 냄), 빈 객체 `anchor_<방id>`(라벨 자리), 재질 이름 `glow*`(불 켜진 창).
- `building/building.js` — 회전·단면·층 고르기·라벨·그림체(툰 4단 명암 + 구운 구석 그늘 + 해 그림자맵 2048 + 4x MSAA + 화면 공간 잉크 외곽선 + 종이 결). 방과 링크는 맨 위 `ROOMS`(사이트 뿌리 기준 경로). 작품이 늘면 `ROOMS` 와 첫 화면의 방 목록을 같이 고친다.
- 콘셉트 그림(나노바나나 초안)은 저장소 밖 프로젝트 폴더에 있다. AI 초안이라 사이트에 올리지 않는다.
- 캐릭터(시로·카피바라씨·코알라씨)는 캐릭터 시트 뒤에 넣는다. `TODO(character-sheet)`.
- `index.html` 은 `building.css`·`building.js` 에 `?v=버전` 을 붙인다. GitHub Pages 는 파일마다 10분 캐시라 새 HTML 과 옛 JS 가 섞이면 새 버튼이 먹통이 된다. 이 두 파일을 고치면 `?v=` 를 릴리스 번호로 올린다.
- three.js r180 과 GLTFLoader 는 `assets/vendor/three/`(MIT) 사본, `importmap` 으로 `three` 를 가리킨다. 외부 스크립트 없음.
- 확대·축소: 두 손가락 벌리기/오므리기, 마우스 휠, +/− 버튼 (`userZoom`, 0.45~1.8배). 가까이 가면 앞 클립면도 당긴다.
- **걷기(1인칭, 기본 모드)** (두호 2026-11-23: 게임처럼 이용하는 사이트): 모델이 뜨면 바로 울타리 문 앞 눈높이(1.45 m)에서 시작한다(`?view=` 가 붙으면 둘러보기로 시작). 키보드 WASD·방향키로 걷고, PC 는 클릭하면 마우스가 잠겨(포인터 락) 움직이는 대로 둘러본다(Esc 로 풀림, 잠기지 않으면 끌어서). 터치는 모바일 FPS 식: 무대 왼쪽 반을 누른 자리에 가상 조이스틱(`#joy`)이 떠서 미는 만큼 걷고, 오른쪽 반을 끌면 둘러본다(두 손가락 동시). 현관 1.8 m 안으로 가면 문짝(`door` 노드, 원점이 경첩)이 안쪽으로 열린다. 찻집 서쪽 벽 계단으로 2층, 그 위 계단으로 루프탑 데크, 집 서쪽 바깥 돌계단 구덩이로 지하실(`floor -1`, 걷기에서만 보임)에 간다. 다락(놀이방·천문대)은 지붕이 낮아 못 들어가고 데크에서 본다 — 집을 다시 만드는 3단계 몫. 발높이는 `surfaceAt()` 이 (x,z) 에 설 수 있는 바닥들(마당·1층·2층·데크·지하·계단 비탈) 중 지금 발높이와 가장 가까운 것을 고르고, 한 번에 `STEP`(0.62 m) 넘게 오르내리지 못하게 해 구멍·난간 밖을 막는다. 벽·가구는 `blocked()` 가 층(발높이)별로 본다 — 계단·지하 수치는 `build_house.py` 의 ST12·ST23·HOLE12·HOLE23·BZ·TRX·CELLAR_DOOR 와 같아야 하고, 모델을 옮기면 같이 고친다. 방에 2.2 m(천문대는 4.5 m) 안으로 다가가면 그 방 이름표 하나만 그 자리 위에 뜨고, 탭·클릭·E 로 연다(인출선 없음). 걷는 동안 벽을 걷어 내지 않고, 층·확대 버튼은 잠긴다. 단추(`둘러보기`)로 예전 모드가 된다.
- **블랙홀멍** (`building/blackhole.js`, 두호 2026-11-23: 불멍·물멍처럼 보고 있는 블랙홀, 인터스텔라풍) — 지하실 북쪽 벽 관측창(모델의 `blackhole` 노드, 재질 `glowhole`) 화소마다 슈바르츠실트 블랙홀 둘레의 휜 광선을 적분해 얇은 강착 원반(fbm 필라멘트·차등 회전·도플러·중력 적색편이)과 별 배경을 그리고, 2단 블룸 + ACES 톤을 얹는다. 모델이 아니라 셰이더라 용량이 없다. 화면의 1/2(폭 720 화소 상한) 버퍼에 그린 뒤 창 화소가 화면 좌표로 읽고, 지하실 안에서 창이 화면에 들어올 때만 그린다. 블랙홀은 '동작 줄이기'와 무관하게 늘 돈다(움직임이 내용). 지하실에서는 해를 끄고 하늘빛을 0.3 배로 줄여 창에서 나오는 주황 점광(`bhLight`, 천천히 일렁임)이 방을 물들인다. 창 치수(가로 ±1.7 m, 바닥 +0.75~+2.15 m)·블랙홀 위치(`BH.CENTER`, 창 9 m 뒤)·배율(0.5 m/단위)·기울기는 `blackhole.js` 의 `BH` 에 있다. 독립 프로토타입(URL 로 각도·시각 조절)은 저장소 밖 프로젝트 폴더 `hub/redesign-2026-11-23/blackhole2.html`. `building.js` 가 `./blackhole.js?v=` 로 불러오므로 `?v=` 는 세 곳(index.html 두 곳 + 이 import)을 함께 올린다.
- `building/model/check.js`(playwright 필요, 선택 도구) — 걷기 검토. 네 화면 크기(PC 넓게·높게, 폰 세로·가로)에서 걷기가 기본인지, 버튼 줄이 화면 안인지, 콘솔 오류 0 인지, 아홉 자리(마당·현관·찻집·계단 중간·2층·루프탑·돌계단·지하실·블랙홀멍)에 설 수 있는지, 일곱 벽을 못 뚫는지, 블랙홀이 창을 볼 때만 그려지고 움직이는지 확인하고 자리마다 캡처한다. `node building/model/check.js . <출력 폴더>`. 걷기·모델을 고치면 PR 전에 돌린다 (전면 개편 계획서의 '오류 0 검토 루프').
- 위아래·좌우로 돌린다(위아래는 거의 눈높이~위에서 내려다보기 사이로 막아 둠). 무대 위에서는 세로로 끌어도 페이지가 스크롤되지 않는다(`touch-action:none`). 기본은 집 전체, 층 버튼(1·2·3층)을 누르면 그 층만 떼어 가까이 보여 준다(땅은 1층일 때만). WebGL 이 없으면 목록만, '동작 줄이기'면 자동 회전 없음.
- 이름표는 무대 가장자리에 세우고 방까지 긴 인출선으로 잇는다(도감처럼). 넓은 화면은 양옆 끝, 폭 520px 미만은 위아래 끝 띠. 카메라 거리가 그 칸만큼 건물을 작게 잡는다(`resize()`).
