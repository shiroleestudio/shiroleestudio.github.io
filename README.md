# shiroleestudio.github.io

이시로스튜디오(아기토끼 시로) 허브 사이트. GitHub Pages로 https://shiroleestudio.com 에 공개된다(저장소 `CNAME` 파일이 주소를 정한다. 도메인·DNS 는 `STUDIO.md`).

구성

- `index.html` — 첫 화면은 3D '시로의 집'(아래 절)만. 머리줄 · 무대(남는 높이 전부) · 조작 안내 한 줄 · 한 줄 바닥글. 작품·소식·이야기·문의는 각자의 페이지에만 둔다. 제목·소개와 방 목록은 화면낭독기·검색엔진용으로 숨겨 두고, 3D 가 안 되면 방 목록이 보인다
- `works/` — 작품 목록, `works/timeline/`, `works/space-surfer/` 소개 페이지
- `news/` + `feed.xml` — 소식과 RSS(Atom). 새 소식은 두 곳에 함께 추가
- `about/` — 시로 이야기, `support/` — 자주 묻는 질문·문의
- `sitemap.xml`, `robots.txt`, `assets/og.png`(공유 이미지), `assets/img/`(스크린샷)
- `favicon.ico` — 루트에 꼭 둔다. 네이버 봇이 수집 때 `/favicon.ico` 를 요청하고 404 면 수집이 실패한다(연표에서 겪은 일). `assets/favicon-32.png` 에서 만든 16·32px 사본이라 아이콘이 바뀌면 함께 다시 만든다.
- `privacy/<앱이름>/` — 앱별 개인정보처리방침 (swingby, timeline, coffee)
- `ads.txt` — 웹 애드센스 판매자 확인(루트 도메인에 두면 timeline. 등 서브도메인까지 적용). 게시자 ID 는 애드센스 계정의 것.
- `app-ads.txt` — 애드몹 app-ads.txt (가입 후 한 줄 채움)
- `404.html` — 없는 주소 안내

규칙

- 외부 스크립트·폰트 없이 정적 파일만 쓴다. 경로는 상대경로(404.html만 절대경로).
- 머리말·꼬리말은 페이지마다 같은 마크업이 들어 있다. 메뉴를 바꾸면 모든 페이지를 함께 고친다.
- 아직 공개되지 않은 곳(예: itch.io 페이지)은 링크하지 않는다.
- 시로 그래픽은 캐릭터 시트 확정 전 임시 표현이다. `TODO(character-sheet)` 주석 참고.
- 개인 실명·소속·직업은 어디에도 넣지 않는다. 문의는 shiroleestudio@gmail.com.
- 릴리스마다 `CHANGELOG.md` 맨 위에 한 줄 추가하고 `vX.Y.Z` 태그를 남긴다.

운영

- 배포: `main` 에 푸시하면 GitHub Pages 가 그대로 올린다(빌드 없음, 1~2분). 상태는 Actions 탭의 "pages build and deployment".
- 되돌리기: 잘못 올라갔으면 `git revert` 로 커밋을 되돌려 다시 푸시한다. 설정을 만질 일은 없다.
- 깨졌을 때 볼 곳: Settings → Pages 의 Source 가 `main` / root 인지. 그 외에는 HTML 문법 오류뿐이다.
- 외부 계정·정기 점검·다른 저장소 목록은 `STUDIO.md`.
- 라이선스: 코드(HTML·CSS·JS)는 `LICENSE`(MIT). 시로 캐릭터 그림과 글은 이시로스튜디오의 것으로, MIT 에 포함되지 않는다.

## 시로의 집 (첫 화면의 3D 건물, 파일은 `building/`)

첫 화면의 주인공. 1층 찻집 · 2층 갤러리(화실+공방) · 3층 다락(놀이방·천문대) + 루프탑, 지붕 위 돔에서 망원경이 나온다. 지하실(돌방, 바깥 서쪽 돌계단으로 내려감) 한가운데에는 블랙홀이 캠프파이어처럼 떠서 돈다('블랙홀멍', 아래). 집 둘레는 게임의 한 장면처럼 동네 터(잔디·돌길·말뚝 울타리·나무·가로등·우편함·뒤편 언덕, 모두 `floor 0`; 서쪽 뒤 연못과 돌계단 입구 화분은 걷기를 막아 2026-11-27 뺐다)이고, 배경은 셰이더가 그리는 하늘(라이트=낮, 다크=별 뜬 밤)이다. 방 이름표가 곧 메뉴이고, 그 방 가까이 갔을 때만 뜬다(두호 2026-11-23: 조감도·둘러보기 모드는 뺐다). 같은 방 목록이 `index.html` 안에 글로 있다(평소엔 숨김, 3D 가 안 되면 보임). 방을 바꾸면 `ROOMS` 와 이 목록을 같이 고친다. `building/index.html` 은 첫 화면으로 넘기기만 한다.

- `building/house.glb` — 모델. **손으로 고치지 않는다.** `building/model/build_house.py` 를 고치고 다시 만든다:
  `pip install bpy pillow` (Python 3.11+, Blender 5.x) 후 `python building/model/build_house.py building/house.glb`, 또는 `blender -b -P building/model/build_house.py -- building/house.glb`.
  스크립트가 모양을 쌓은 뒤 ① 큰 면을 잘게 나누고 구석 그늘(AO)을 광선으로 재어 정점색 `COLOR_0` 에 굽고, ② `building/model/textures.py` 가 그린 나뭇결·지붕널·회벽·돌·풀 텍스처(색 1024²·높이에서 만든 법선·거칠기 ORM, WebP, 1 타일 = 1 m)를 상자 투영 UV 로 입힌다(법선·거칠기는 색만 다른 변형끼리 한 벌). 법선은 넣지 않는다(면이 평평해 사이트가 계산해도 같다, 용량 25% 절약). 결과는 약 2.3 MB(계단·지하실 포함).
  손그림 텍스처가 생기면 `textures.py` 의 `RECIPES` 에서 그 그림 파일로 바꿔 끼운다.
- `building/house.webp` + `assets/og.png` — 정지 그림(마당 구석에서 집을 본 1인칭 시점). 3D 가 안 되는 기기와 공유 미리보기에 쓴다. 모델·그림체가 바뀌면 `building/model/still.js`(playwright 필요, 선택 도구)로 다시 찍는다.
- `building/house.lightmap.webp` — **라이트맵**(2026-11-24). `build_house.py` 끝의 `bake_lightmap()` 이 Cycles(CPU) 로 굽는다: 큰 면(벽·바닥·지붕·땅·지하·데크·계단·도머·굴뚝)에 두 번째 UV(`LM`, glTF TEXCOORD_1)를 펼쳐 한 아틀라스(2048²)에 담고, 베이크 1(해만, 반사광만) + 베이크 2(하늘만, 직접+반사)를 더해 sRGB(값/2)로 저장. 8각 통나무·널빤지 틈으로 빛이 새지 않게 베이크 때만 벽 속에 가림막(`bake_occluder`)을 두고 내보내기 전에 지운다. 사이트는 `uv1` 이 있는 메시에만 `lightMap`(**`channel = 1`** 필수 — 0 이면 색 텍스처 좌표로 아틀라스가 타일링돼 벽이 얼룩진다; 세기 낮 1.5·밤 0.5)을 입히고 해 직접광·그림자는 실시간으로 그린다. 소품·나무·문은 정점 AO 만. 2048²·48 샘플이 약 8분, `HOUSE_LM=1024`(20 샘플)는 1분 반 — 고칠 때는 1024 로 보고 마지막에 2048. `HOUSE_LM=0` 이면 건너뛴다. 지오메트리를 바꾸면 다시 굽는다.
- `building/assets/` — **에셋 폴더**(두호 2026-11-23). 손으로 만든(또는 CC0 사진) 텍스처(`textures/<재질키>.(png|jpg|webp)`, 선택으로 `_n`·`_orm`)를 넣으면 `build_house.py` 가 생성 텍스처 대신 쓴다. 2026-11-24 부터 마루·널빤지·기둥·회벽·돌·잔디·통나무는 ambientCG CC0 사진(출처는 `textures/SOURCES.md`), 지붕널만 생성. `models/`(손 모델 glb, 아직 빌드가 읽지 않음)·`reference/`(참고 그림). 자세한 약속은 그 폴더의 README.
- 모델과 코드의 약속: 노드 extras 의 `floor`(층, 0=땅, -1=지하실)·`cut`(S/N/E/W; 둘러보기가 없어진 뒤로 사이트는 안 쓰지만 모델엔 남겨 둔다), 빈 객체 `anchor_<방id>`(이름표 자리), 재질 이름 `glow*`(불 켜진 창).
- `building/building.js` — 1인칭 걷기·이름표·그림체. **그림체(3단계 그래픽 일신, 2026-11-23, 두호: '8번 출구'급 실사 + 몽환적 판타지 동화풍)**: 모델의 PBR 재질(색·법선·거칠기 지도)을 그대로 쓰고(`MeshStandardMaterial`, 구석 그늘 정점색 곱함, 이방성 필터), 해 그림자맵 2048(PCF soft) + 하늘빛 반구광 + 하늘 환경광(작은 하늘 공을 PMREM 으로 구움, 테마마다 다시) 으로 비춘다. 장면은 HDR(HalfFloat, 4x MSAA) 로 그리고 후처리에서 ① 셰이더 하늘 배경(지평선→천정, 해 무리, 흐르는 구름 / 밤: 별·달) ② 거리 안개(낮 0.006·밤 0.010, 지하실 0) ③ 블룸(1.5 넘는 밝기, 1/4·1/8 흐림 — 창·블랙홀·해 무리) ④ ACES 톤 + 색 보정(그늘 살짝 보라, 밝은 곳 따뜻하게, 채도 1.12, 약한 S 대비) ⑤ 비네트·고정 필름 그레인·가장자리 색수차 를 얹는다. 창은 유리(`glow` 재질 → 반투명 `MeshStandardMaterial`, 낮엔 하늘이 비치고 안이 들여다보이며 밤엔 발광 2.6 으로 번진다, 해를 가리지 않음); 전구(`glowbulb`)는 조명 없는 재질에 HDR 배율(낮 1.6·밤 3.2). 라이트맵(위 `house.lightmap.webp`)이 큰 면의 하늘빛·반사광을 맡으므로 반구광은 낮 0.42·밤 0.6 으로 낮다(소품은 이 값만 받는다). 잉크 외곽선·종이 결(v0.8~0.10 툰 그림체)은 뺐다. 방과 링크는 맨 위 `ROOMS`(사이트 뿌리 기준 경로). 작품이 늘면 `ROOMS` 와 첫 화면의 방 목록을 같이 고친다.
- 콘셉트 그림(나노바나나 초안)은 저장소 밖 프로젝트 폴더에 있다. AI 초안이라 사이트에 올리지 않는다.
- 캐릭터(시로·카피바라씨·코알라씨)는 캐릭터 시트 뒤에 넣는다. `TODO(character-sheet)`.
- `index.html` 은 `building.css`·`building.js` 에 `?v=버전` 을 붙인다. GitHub Pages 는 파일마다 10분 캐시라 새 HTML 과 옛 JS 가 섞이면 새 버튼이 먹통이 된다. 이 두 파일을 고치면 `?v=` 를 릴리스 번호로 올린다.

- **걷기(1인칭, 유일한 모드)** (두호 2026-11-23: 게임처럼 이용하는 사이트): 모델이 뜨면 바로 울타리 문 앞 눈높이(1.45 m)에서 시작한다. 키보드 WASD·방향키로 걷고, PC 는 클릭하면 마우스가 잠겨(포인터 락) 움직이는 대로 둘러본다(Esc 로 풀림, 잠기지 않으면 끌어서). 터치는 모바일 FPS 식: 무대 왼쪽 반을 누른 자리에 가상 조이스틱(`#joy`)이 떠서 미는 만큼 걷고, 오른쪽 반을 끌면 둘러본다(두 손가락 동시). **세로 폰**(터치 기기 + `orientation:portrait`, 두호 2026-11-26; 터치 기기는 `navigator.maxTouchPoints` 로 판정해 `<html class="touch">` 를 단다 — S펜 폰처럼 `hover:hover` 를 내는 기기가 있어 hover 쿼리로는 안 된다)은 무대를 16:10 으로 줄이고 그 아래 띠에 가상 게임패드(`#pad`)를 둔다: 왼쪽 고정 스틱(PSP 식, `#padStick`, 반지름 40 px 안에서 미는 만큼 걷기)과 오른쪽 터치패드(스팀 컨트롤러 식, `#padLook`, 끌면 둘러보기 — 감도 0.0048, 8 px·400 ms 안의 톡은 가까운 방 열기). 무대 위 터치도 그대로 되고, 가로 폰·PC 는 패드가 없다(`building.css` 의 미디어 쿼리). 평평한 선 그림, 사이트 토큰만 쓴다. 현관 1.8 m 안으로 가면 문짝(`door` 노드, 원점이 경첩)이 안쪽으로 열린다. 찻집 서쪽 벽 계단으로 2층, 그 위 계단으로 루프탑 데크, 집 서쪽 바깥 돌계단 구덩이로 지하실(`floor -1`, 걷기에서만 보임)에 간다. 다락(놀이방·천문대)은 데크에서 서쪽 지붕면에 낸 도머 입구(`build_house.py` YD0·YD1·XD)로 걸어 들어간다 — 용마루 아래 2.7 m 라 가운데 띠(|x−1.2| < 0.98)만 서고, 지붕이 낮은 양옆은 `blocked()` 가 막는다. 발높이는 `surfaceAt()` 이 (x,z) 에 설 수 있는 바닥들(마당·1층·2층·데크·지하·계단 비탈) 중 지금 발높이와 가장 가까운 것을 고르고, 계단 띠(SX0..SX1 × 비탈 z 구간) 위에서는 그 아래층 바닥을 후보에서 뺀다(안 빼면 아래층이 늘 가장 가까워 계단 밑을 지나간다 — 2026-11-26). SX1 은 위층 구멍 HOLE12·HOLE23 의 동쪽 끝과 같아야 꼭대기에서 위층으로 건너갈 틈이 없다. 한 번에 `STEP`(0.62 m) 넘게 오르내리지 못하게 해 구멍·난간 밖을 막는다. 벽·가구는 `blocked()` 가 층(발높이)별로 본다 — 계단·지하 수치는 `build_house.py` 의 ST12·ST23·HOLE12·HOLE23·BZ·TRX·CELLAR_DOOR 와 같아야 하고, 모델을 옮기면 같이 고친다. 방에 2.2 m(천문대는 4.5 m) 안으로 다가가면 그 방 이름표 하나만 그 자리 위에 뜨고, 탭·클릭·E 로 연다 — 이것이 메뉴다. 벽은 걷어 내지 않는다.
- **블랙홀멍** (`building/blackhole.js`, 두호 2026-11-23: 불멍·물멍처럼 보고 있는 블랙홀, 인터스텔라풍, "지하실 한가운데에 캠프파이어처럼", "지하실을 거의 꽉 채우는 느낌") — 지하실(2026-11-25 두호 '높이를 높이고' — 바닥 −4.2 m, 천장 높이 4.2 m, 돌계단 18단) 한가운데(바닥 위 1.1 m) 반지름 2.1 m 공(`bhSphere`, 코드가 만든다; 벽 안에 들어가야 한다) 화소마다 카메라에서 광선을 쏘아 슈바르츠실트 블랙홀 둘레의 휜 경로를 적분하고, 얇은 강착 원반(바깥 반지름 10 단위 = 그림자의 약 4배, 인터스텔라 참고 이미지 비율; **거리 압축**(2026-11-25 두호 '현실성을 좀 무시해도 돼, 가까이 갈수록 진짜 블랙홀 크기처럼 커 보이게'): 실제 거리 0.7~3.2 m 를 셰이더 거리 3~16 단위로(지수 보간, 가까울수록 급히) 옮기고 앙각은 벽가 2배→가장 가까이 0.3배로(`BH.dist`·`BH.tilt`) 다가갈수록 눈이 원반 높이로 내려가 강착원반 위를 걷는 느낌이 되고, 지평선이 눈앞에 벽처럼 선다(두호: 위에서 보는 게 아니라 원반에서 걷는 느낌). 시선은 블랙홀 중심이 실제 자리에 보이도록 되돌린다(`qFix`); 반지름 색 램프(흰 크림→노랑→주황→적갈색), 나선으로 늘인 낮은 대비 fbm 실(가는 동심원 줄무늬 금지 — 매끈해야 한다), 원반 위아래 빛안개, 차등 회전·도플러 빔 δ³(β=1/√(2(r−1)), gargantua-cinema 의 식)·중력 적색편이 √(1−1/r))을 지나는 빛을 모은다. 지평선은 검정, 비껴간 광선은 투명(방이 비쳐 보인다). 2단 블룸 + ACES. 모델이 아니라 셰이더라 용량이 없다. 버퍼는 PC 에서 화면 화소 그대로(폭 1600 상한), 터치 기기는 0.75(폭 1200 상한)이고(두호 2026-11-24 '블랙홀만이라도 고해상도로'), 지하실 프레임이 34 ms 를 넘으면 `bhGovern()` 이 한 단씩(×0.8, 최저 0.4) 줄이고 14 ms 아래면 다시 올린다. 광선은 0.05 r 걸음으로 최대 360회. 미리 곱한 알파로 그린 뒤 공의 화소가 화면 좌표로 읽고, 지하실 안에서 공이 화면에 들어올 때만 그린다.
